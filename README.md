# 油记（FuelNote）

在 Scripting 里运行的油耗与用车账本：

- 记加油和费用，自动算油耗。
- 数据都存在油记里。可以从小熊油耗导入，需要时再手动导出到小熊（2.0.0-beta.6 起）。
- 可以从数据源插件读取行程、车况和养修（例如沃尔沃插件），填入里程、时间、油站和费用。
- 小组件、锁屏和记录页写出加满这一箱要多少钱：按所在地区的挂牌价和车辆的默认标号算，油价由数据源插件提供（2.4 起）。
- 小组件的格子里放什么可以选，每个小组件用「参数」选一套方案（2.5 起）。
- 数据源插件可以给信息卡片（例如今天附近油站的优惠），写在记录页和小组件里（2.6 起）。
- 记下每年的保单明细：选保单 PDF 自动填好，看历年保费，到期前提醒续保，出险时一键报案。

设计与实施：

- 设计文档：`docs/specs/2026-10-18-fuelnote-design.md`
- 实施文档：`docs/plans/2026-10-18-fuelnote-v1.md`；保险与权益（1.5–1.8）：`docs/plans/2026-10-21-insurance-benefits.md`
- 2.0（以油记为准）：`docs/specs/2026-10-24-local-first.md`、`docs/plans/2026-10-24-v2-local-first.md`

## 安装

安装包固定地址（总是最新版本）：

```text
https://github.com/fuelnote/fuelnote/releases/latest/download/FuelNote.zip
```

在 Scripting 中用这个地址导入脚本。`script.json` 的远程资源也是这个地址，Scripting 每天检查一次更新：

```json
"remoteResource": {
  "url": "https://github.com/fuelnote/fuelnote/releases/latest/download/FuelNote.zip",
  "autoUpdateInterval": 86400
}
```

更新只替换脚本文件。记录、小熊的导入状态和缓存在 Scripting 的 App Group 目录，凭据在钥匙串，都不受影响（见「凭据与数据」）。

各版本的改动见 [CHANGELOG.md](CHANGELOG.md) 和 [Releases](https://github.com/fuelnote/fuelnote/releases)。

## 入口

- `index.tsx`：主界面，分油耗、费用、保险、权益、设置五个标签。油耗和费用的统计在各自右上角的统计图标里，互不混在一起。
- `intent.tsx`：快捷指令和分享面板的入口。快捷指令「截屏」→ Scripting「在 App 里运行意图：油记」（截屏放在「图像」一栏）绑在轻点背面上，在账单详情页轻点两下即可打开已识别、已配对加油停车的记加油表单（设置 › 截屏记加油 有步骤）。
- `widget.tsx`：桌面小组件（小号、中号）和锁屏小组件（矩形、圆形、单行），点击直接打开「记加油」；中号左侧打开油记首页。油记已经打开时，不会再开一个。大字是最近油耗和与平均的对比；关联了沃尔沃的车另外显示剩余油量（小号右上角、中号右侧、锁屏圆环），车况超过 1 小时时小组件自己读一次。小号、中号下面有「记加油」按钮。视图在 `widget_view.tsx`；2.5 起大数字、四格和锁屏圆形的中间按「设置 › 小组件 › 方案」放内容，「参数」填方案的名称；2.6 起「这一箱」和大号的「最近加油」可以换成插件的信息卡片。

## 使用

### 开始记账

点「油耗」页左上角的车辆按钮 ›「添加车辆…」（或「设置 › 车辆 › 添加车辆」），然后点右上角的「+」记加油。其他费用在「费用」页点「+」记费用；车险在「保险」页点「+」记保险。

- 添加车辆与小熊油耗的建车流程相同：名称、车型（品牌 → 车系 → 车型，来自小熊的车型库，可以不选）、默认标号（按车型预填）、购车日期，还可以关联沃尔沃的车。
- 多辆车时，在油耗、费用、保险页左上角的车辆菜单里切换。暂时不用的车可以在车辆页「隐藏这辆车」，记录照常保留。

- 单价、升数、机显金额任填两项，自动算出第三项。
- 实付默认等于机显金额。
- 油耗按跳枪法计算：两次加满之间为一段，结果显示在后一次加油上。

### 用截图或照片记加油

记加油表单最上面的「自动填写」：点一张最近的付款截图，或「拍照」「相册」「粘贴」。

- 识别方式在「设置 › 识别方式」选一种（添加权益时的识别也用它）：
  - 本机：iOS 文字识别，离线，默认；
  - 大模型（Azure OpenAI）：需要填写终结点、部署名、key；
  - 大模型（Scripting 助手）：用你在 Scripting 中绑定的模型账号（如 OpenAI），在设置里选模型，油记不保存它的凭据。需要 Scripting PRO。
- 读到的单价、升数、金额互相核对不上，或实付找不到依据时，照样填入，并提示对照图片检查。
- 识别出的单价、升数、金额、实付、时间、标号自动填好，字段名后面标出来源（截图、照片、拍照）。
- 图上没有标号时按单价对照当天当地的 92# 油价判断，标「油价 ⓘ」，点开能看依据、改标号。
- 有付款时间且关联了沃尔沃时，自动用付款前最近的一次加油停车填好里程和油站。之后「更换」停车，时间仍是付款时间。
- 单价 × 升数与金额对不上时不能保存，表单给出两种改法，请对照原图选择。

### 油耗和费用

- **油耗**：只有加油。「记录」最上面是车况（关联了沃尔沃时），下面按月列出加油，月合计只算加油；「统计」是平均油耗、每公里油费、每月加油、同期对比、单价和每年。小组件的「本月油费」「今年油费」也只算加油。
- **费用**：车险以外的费用：保养、停车、洗车、年检等。按年列出，组头是这一年的合计；右上角的统计图标是合计和分类、每年（按付款日期），不含车险。一次保养（保养记录和对应的那笔维修保养费用）只显示一行、只算一次。
- **记费用**：顶部的分段选类别（小熊的类别，按小熊里的顺序，不含「保险和交通规费」），默认最近一笔费用的类别；切换类别时已填的内容保留。
- **记保养**（2.1）：记费用选「维修保养」时多一组「保养」：里程（默认取车况的里程表）和项目（输入，或从用过的项目里点，按用过的次数排）。填了项目才另存一条保养记录，费用页里和这笔费用合成一行。轻点这一行，保养和费用一起改（类别锁住）；左滑删除时两条一起删。
- **费用的标题**（2.3）：记费用、编辑费用的最上面一行「标题」，就是费用页这一行写的名字，可以改。空着时自动写：换了机油的保养写「第几次保养」，其他保养写说明的第一行（没有说明时写项目），其余写备注的第一行，都没有时写类别名；表单里用灰字写出来。导出到小熊时，标题写成费用备注的第一行。
- **从沃尔沃选**（2.3，关联了沃尔沃时）：记费用最上面「自动填写」里的「从沃尔沃选」，列出沃尔沃里已结算的进店，新的在前，右边是要记几笔。选中一次进店，整次填好：第一笔填进表单（保养的里程是到店里程，项目照沃尔沃工单上的叫法，第二行写来自哪个工时，检查写进备注），其余每张工单各「另记一笔」（标题是沃尔沃给的，可以改；关掉的不记）。金额一栏叫「实付」：自付为 0 时填 0，否则要自己填（沃尔沃的自付不一定是实付）。门店按经销商的名称或位置找到，旁边标「沃尔沃」；能按工单判断的权益先勾好、标橙；结算明细只读显示，使用权益页上面列出这一笔的券对照着勾。保存时同一天、同一类、同样金额已有一笔的，提示「可能重复」。记下以后是普通的费用：编辑时有一行只读的「来源 沃尔沃」和结算明细。油记不判断哪次进店记过；漏记由自己管，记重了由「可能重复」拦下。
- **来源**（2.3）：从数据源选来填的加油（从易捷选）和费用（从沃尔沃选）记下来源，编辑时最上面（费用在标题下面）一行只读显示；数据源移除以后照样显示。

### 保险

「保险」页记每年的车险：

- **记保险**：点保险页右上角的「+」，选择这一年的保单 PDF 或图片（可以多选）。交强险、商业险是统一格式，保费、浮动比率、车船税、每个险种的保额和保费都会读出来，并核对各项之和与大写金额；驾乘意外险等其他保单读出名称、保费和期间。读不出文字的 PDF（扫描件、特殊字体）逐页截图后在本机识别，图片直接在本机识别，都不上传。交强险标志（单独的 PDF、图片，或交强险保单里的一页）挂到当年的交强险上，当前保单用标志徽章显示到期年月，轻点全屏显示标志；都没认出的文件作为附件保存。也可以手动添加保单。
- 保存时在费用里记一笔「保险和交通规费」（金额是保费加车船税减优惠，日期是付款日期）。已经记过这一年的保险费用时（例如从小熊导入的），补到那笔费用，不再重复记（从「只有金额」点「补充保单」，或新记时打开「补到已有的费用」）；金额不同时可以保留原金额。补到哪笔、金额怎么处理只在第一次决定，之后编辑不再问。
- **历年保单**：每年的保费和构成、比上一年的变化，中间缺的年份。正在保障的那一年展开成卡片：交强险标志徽章（轻点全屏显示标志）、期间、还有几天到期、「报案」拨打保单上的电话、「保单」打开原件。只记了金额的车险单独一组：轻点补充这一年的保单，左滑删除这笔费用。
- **保单详情**：轻点一年打开。实付和构成，每个险种和去年的对比，交强险的浮动比率，保单号（点一下复制），保单原件；右上角编辑，最下面删除。
- **续保提醒**：到期前 45 天起，在保险页最上面提醒；记了下一年的保险或点「×」后不再提醒。
- 保单明细只存在本机（小熊没有这类数据），跟着备份走；保单原件存在油记里，不在备份文件里。

### 权益

「权益」页像卡包：每项权益是一张卡，写着来自哪里、剩多少、什么时候到期。

- **添加**：点右上角的「+」，选车险赠送（选哪一年的车险，有效期默认取保险到期日）、保养套餐（填价格和购买日期，可以同时记一笔维修保养费用，只记这一次）或其他。可以粘贴销售发来的文字或选截图，用「设置 › 识别方式」选的大模型整理成几项，确认后保存；保单自带的服务（代驾、道路救援）和已有的同名默认不勾。文字发出前去掉手机号、证件号、车牌和车架号。保单详情里还没有赠送时，「赠送」一行的「添加」直接打开这一年。
- **权益页**：按来自分组、按到期排，每张写剩余；到期前 30 天起组头标橙。左滑删除一张；轻点组名进这一批，可以添加一项、改整批的有效期和门店、删除这一批；最下面是「已用完和已过期」。
- **使用**：记费用时选门店和「使用权益」（列出那天在有效期内、还有剩余的卡；有效期起默认是买保险那天或添加那天，在编辑里可以改）：储值（维修保养券这类一笔钱）填抵扣金额；次数（服务、抵用券）只记用掉几次，不抵钱，金额直接填实付；费用记实付；门店和用了哪些权益记在这笔费用上，备注只留你写的内容（导出到小熊时才写进备注的最后一行）。不花钱的使用（车内杀菌）在权益详情里「记一次使用」。删除费用时它用的权益恢复；删除权益卡时记过的费用不变。
- 保单详情的「赠送」一行列出这一年送了什么；续保提醒写出同一天到期、还没用完的赠送；费用统计有「权益抵扣」。
- 门店在「选择门店」页里，都是系统地图上的地点（2.2 起，不要 Key）：顶部搜索，先列手机附近的（第一次搜索时系统会问定位权限，取不到位置时以最近用过的油站为准）；我的门店按最近用过的排，第二行写地址；记费用时还列出那时停车的地方附近 1500 m 内的汽车服务，按距离排。选中一家就存进我的门店，名称默认取地图上的名称（去掉括号里的分店名）；我的门店里已有同名、相距 80 m 内的，直接用那一家。轻点 ⓘ 看门店详情：改名称、拨电话、在系统地图中打开、重新定位、删除。费用备注里写的店名不会当成门店。删除门店时，记过的费用和权益卡去掉门店，金额不变。
- 权益、使用记录和门店只存在本机，跟着备份走。

### 从小熊油耗导入

1. 在 Surge 中启用「小熊油耗 · 凭据抓取」，打开小熊油耗 App 的会员页；然后在 BoxJS 中复制 `xxyh_auth`。
2. 打开「设置 › 小熊油耗」，粘贴后点「连接」。列出小熊里还没导入的车（第一次连接时默认全选），勾选后点「导入」。
3. 导入后记录都存在油记里，小熊里的数据不动。已经导入的车不再导入；要重来，先在油记里删掉这辆车。之后在油记里记账不会自动上传。
4. 需要时手动导出到小熊（2.0.0-beta.6 起）：
   - 车辆页「导出到小熊油耗」选这辆车导出到小熊里的哪辆车，或在小熊新建一辆。
   - 「设置 › 小熊油耗 › 导出到小熊油耗」：先下载小熊云端最新的版本，按车列出加油、费用、保养的新增、修改、删除，确认后上传成一个新版本。小熊里在上次导出后有改动时会标出来，导出会用油记的记录覆盖。
   - 第二行写上次导出的时间和还没导出的修改条数（按上次的版本离线算）。

注意：

- 保险明细、权益和门店只在油记里（小熊没有这类数据）。
- 小熊的原始字段跟着记录保存，导出时油记不认识的字段原样写回。
- 保养记录只能查看（2.1 起可以编辑）。

### 连接沃尔沃

1. 沃尔沃是另装的数据源插件（2.3 起，私有，另外提供）。装好以后在「设置 › 数据源 › 添加插件」里添加；插件自己从 BoxJS 读凭据，连接、断开都在插件的页面里。
2. 编辑车辆，在「车辆数据」里关联沃尔沃的车。2.2 关联过的车不用重选。
3. 记加油时，表单最上面的「自动填写」会显示最近 2 天里还没记录的加油停车，点「填入」就填好熄火时的里程、时间和油站，这几项旁边标「行程」。
4. 要用别的停车时，点「从行程选择」：
   - 列出最近 7 天的停车，加油停车排在前面；
   - 选中后填入熄火时的里程、时间，以及油站；
   - 下拉可以重新读取。

行程 10 分钟内只读一次，表单和从行程选择共用；附近加油站的搜索结果按地点保存 30 天。

加油停车的判断规则：

- 离「我的油站」80 m 以内，且停留不超过 45 分钟；或者
- 停留不超过 30 分钟，且附近 60 m 内有加油站。

附近的加油站用系统地图搜（2.2 起），不要 Key，也不用设置。选择油站的搜索框和门店一样，先列手机附近的。

### 数据源插件

插件是独立的 Scripting 脚本，只提供数据（例如加油交易、所在地区的挂牌价）；记账和核对都在油记里做。

1. 先把插件装进 Scripting。
2. 打开「设置 › 数据源 › 添加插件」：只列出带油记插件标记（`fuelnote.json`）的脚本，不运行其他脚本。选中后油记运行一次这个插件，确认版本和提供的数据再添加。
3. 轻点插件进入详情：看连接状态和打码的账号；「管理连接」打开插件自己的页面；「移除插件」只从油记里去掉，不删脚本，也不动插件里的凭据。
4. 设置里每个插件写着手机上装的版本（2.7 起）。插件详情的「提供的数据」轻点一行启用或停用：只想用其中几项时，停用其余的，油记就不再请求这几项数据。插件声明的每张信息卡片各占一行（例如易捷的「今天的优惠」），可以分别启用、停用。车辆不单列，随行程、车况、养修使用（要先在车辆设置的「车辆数据」中关联车辆）。全部停用就是暂停这个插件：油记不再运行它，设置都留着，随时启用。

[示例插件](https://github.com/fuelnote/fuelnote-plugin-example)返回编的加油交易、车况和信息卡片，可以拿来试用。

插件可以给信息卡片（2.6 起，例如易捷插件的「今天的优惠」）：记录页「当前」下面每张卡片一组，写摘要和条数，轻点弹出全部；没有车况的车写在记录页最上面。插件给了地点的一行，长按可以用高德地图、百度地图或苹果地图导航。打开油记时，卡片过了插件给的有效期、或者默认标号、所在的省市变了才查，在后台一批一批地查；点开的一页里可以「重新查」。「设置 › 小组件 › 方案」里可以把「这一箱」「最近加油」换成卡片。

记加油时从插件选：「自动填写」里截图图块下面的「从<插件名>选」（从快捷指令截屏打开时没有）。

- 表单已有时间时列前后 1 天的交易，离它近的在前；没有时按月分组、新的在前，一开始列本月和上月，最下面「加载更早的交易」一次往前加载一个月。下拉刷新会重新读（没有时间时只重读本月和上月）。从插件填入以后点「更换」：时间就是那笔交易给的（没手动改过）时，按月列出、加载到上次加载到的月份，原来选的几笔已经勾上。
- 可以选一笔，也可以选几笔合成一次加油（例如油卡余额不足、再用钱包补足）：升数、机显金额、实付相加，时间取最早一笔。单价不同、油站不同的几笔不能合成；相隔超过 15 分钟只提醒。
- 填入以后和截图识别一样配停车、填里程，字段旁标插件的名称。油站按顺序定：到站停车附近的我的油站、停车附近站名对得上的地图加油站、交易坐标附近的我的油站、交易坐标附近站名对得上的地图加油站，都没有时按交易新建。停车离付款的油站超过 500 m 时提醒核对里程。
- 前后 1 小时内已有加油时提示可能重复；同一次加油记两次、里程也一样时不能保存。

## 凭据与数据

- 凭据只保存在本机钥匙串。插件的凭据存在插件自己那里，油记读不到，也不在油记的备份里。
- 数据文件在 Scripting 的 App Group 目录 `FuelNote/` 下：
  - `ledger2.json`：车辆和记录、每年的保险明细、权益和门店；
  - `insurance/`：保单原件（PDF、图片），跟着备份走；
  - `xxyh2.json`：小熊的账号，上次导入或导出的版本；
  - `xxyh_snapshots/`：最近 5 个小熊版本（导出时用）；
  - `widget.json`：小组件显示的数字，由油记自动生成；
  - `cache/`：行程、附近油站、小熊车型库、车况、插件的加油交易、油价、信息卡片的缓存，删掉也没关系。
- 「设置 › 数据 › 备份与恢复」：
  - 一份备份是一个 zip：车辆、记录、油站、保险明细和保单原件、权益、门店、设置，以及小熊的账号和最近一个版本。都放在 iCloud 云盘 › Scripting ›「油记备份」（没开 iCloud 时写在本机，设置里标橙）。
  - **自动备份**（默认打开）：改了数据就自动备份——保存后 1 分钟内没有新的修改、或离开油记时写一份。最近 7 天每天留一份，再往前每周留一份、留 4 周，每月留一份、留 12 个月。设置首页「备份与恢复」一行写上次的时间，失败时标橙。
  - **包含凭据**：打开时设一个备份密码，由它生成一次密钥（约 1 秒）存在这台手机上，密码本身不保存；之后自动和立即备份都带用它加密的凭据（PBKDF2-SHA256 + AES-256-GCM）。改了密码，之前的备份还要用旧密码。zip 里的保单原件、保单号、车架号不加密，建议打开 iCloud 的「高级数据保护」。
  - **立即备份**：马上写一份「手动备份-…zip」，不会自动删掉；**另存一份**：把最新的一份交给分享面板，存到别处或隔空投送。
  - **从备份恢复**：列出「油记备份」里的全部备份，也可以从其他位置选一个 zip。先看备份里有什么，再整份替换本机数据和保单原件；替换前自动另存一份「恢复前-…zip」（只留最近 5 份）。带凭据的备份，输入备份密码一起恢复凭据，不填就只恢复数据。2.0 以前的备份不能恢复。
- 删除脚本前建议先备份。删除脚本本身不会删掉 App Group 目录里的数据，但重装、换手机时备份最稳妥。

## 开发

在 `E:\scripting` 运行开发服务器，手机上的 Scripting 连接后选择本脚本：

```sh
npx scripting-cli start
```

检查与测试（在本目录）：

```sh
npm install
npm run check                                    # tsc，用 ../../dts 的 Scripting 类型
npm test                                         # Node 单元测试（合成数据）
XXYH_ROOT=E:/GitHub/xxyh npm test                # 另外与真实数据核对（只读）
LIVE=1 XXYH_ROOT=E:/GitHub/xxyh npm test         # 另外在线只读：小熊下载最新版本
```

- 真实数据只从 `XXYH_ROOT` 读取，不提交到本仓库。行程回放和养修的真实数据测试读 `XXYH_ROOT/out/plugin_data/`：沃尔沃插件导出的契约格式的行程和进店。
- 在线测试会拒绝所有写入请求。

### 发布

推送 `vX.Y.Z` 标签后，GitHub Actions（`.github/workflows/release.yml`）自动发布：

1. 核对标签在 `main` 上，标签版本与 `script.json` 一致，远程资源地址指向 `releases/latest/download/FuelNote.zip`、每天检查一次；
2. 跑单元测试（合成数据）；
3. 只把运行需要的文件打成 `FuelNote.zip`：`script.json`、`index.tsx`、`widget.tsx`、`widget_view.tsx`、`intent.tsx`、`README.md`、`CHANGELOG.md` 和 `app/`、`common/`、`pages/`、`platform/`、`providers/`、`readers/`、`stations/`、`sync/`。`docs/`、`tests/`、`tools/`、`node_modules/` 等开发文件不打包，混进去时发布失败；
4. 用 `CHANGELOG.md` 里这个版本的一节作为发布说明，上传 `FuelNote.zip`。

步骤：

```sh
# 1. 在 CHANGELOG.md 最上面写好「## 1.2.0 — 日期」一节
npm run bump -- 1.2.0          # 改 script.json、package.json、package-lock.json
git commit -am "release: 1.2.0"
git tag -s v1.2.0 -m 1.2.0
git push origin main v1.2.0
```

测试版用 `1.2.0-beta.1` 这样的版本号，标签 `v1.2.0-beta.1` 发布为 pre-release。新增顶层源码目录时，要加到 `release.yml` 的「Prepare package」，`tests/release.test.ts` 会检查。

### 接入新的车辆数据提供方

1. 新建 `providers/<brand>.ts`，实现 `VehicleDataProvider`（`providers/types.ts`）。坐标转成 WGS-84，里程转成公里。
2. 在 `providers/registry.ts` 中登记。

设置页和「从行程选择」都通过接口使用提供方，接入新品牌不用改界面。

### 写数据源插件

不改油记也能接入别的数据：写一个 Scripting 脚本，实现 `docs/plugins.md` 里的契约，文件夹里放 `fuelnote.json`。从[示例插件](https://github.com/fuelnote/fuelnote-plugin-example)开始最快：它是模板仓库，README 是接入指南。
