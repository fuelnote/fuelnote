# 油记 2.6：插件的信息卡片 — 实施文档

- 设计：`docs/specs/2026-11-04-presets-and-cards.md` 第 7 节（D14–D28 已定，用户 2026-11-04；契约的字段在用户说「开始实施」时一并确认；D29、D30 是实施时补的，用户同日确认；用户在手机上看了 beta.1，同日改了 D4、D14、D21、D25、D30，加了 D32，画稿第二十八轮）。规则和用例只写在设计里，本文只引用节和用例编号。
- 油记只认卡片，不认卡片里写的是什么（D1、D16、D20、D27、D28）：油记里不出现「优惠」「站」「按天」这类某一种卡片的规则。

- 约定沿用 `CLAUDE.md`：纯逻辑放 `common/`；`pages/` 只从 `common/model.ts` 导入；`widget.tsx` → `widget_view.tsx` → `common/widget_runtime.ts`；泛型写成函数声明或 `<T,>`；可选属性不传 `undefined`。
- 每个测试版：先写 CHANGELOG → `npm run bump -- x.y.z` → `npm run check` 和 `XXYH_ROOT=E:/GitHub/xxyh npm test` 都退出 0 才提交 → `git tag -s`，不推送 → 跑 FuelNote Check、看完截图 → 再请用户看剩下的项目。
- 写代码按测试先行：每一步先写用例编号对应的测试，看它失败，再写实现。

  - `CAPABILITIES`、`CAPABILITY_TITLES`（`info: "信息"`）、`PLUGIN_TIMEOUT_MS`（`info: 20_000`，D23）。
  - `parseDescribe` 读 `cards`：每项要有 `id`、`title`（文字），同一个 `id` 只留第一个；提供 `info` 却没声明卡片时 `cards` 是空的。`pluginRef`、`refreshedRef` 带上 `cards`（声明变了也算插件有更新）。

- [x] `docs/plugins.md`：第 8 节后面加「9. 信息卡片（2.6 起）」：`describe` 的 `cards`，动作 `info` 的参数和返回、卡片的字段、分批（`next`）、一批最多等 20 秒、在后台调不弹页面、位置由插件自己取（D22）、`summary` 和 `empty` 16 个字以内、油记只看 `until` 重查（D20）。原来的第 9–11 节顺延成第 10–12 节，引用的地方跟着改（`grep -rn "plugins.md.\{0,3\}第 \(9\|10\|11\) 节"`）。第 4 节的表加一行。

### 什么时候查（纯逻辑，设计 7.2 节）

- [x] `common/info_cards.ts`（新）：

### 查（应用层）

- [x] `app/info_cards.ts`（新）：

## 手机上的验收（2.6）

1. 打开油记：记录页「当前」下面多一组「今天的优惠」，先写进度，再写最近的一条和「共 N 条」；轻点弹出全部，和易捷 App 里这些站的优惠对得上。
2. 「当前」和车况详情里不再有优惠。
3. 小组件方案里把中号的「这一箱」换成「今天的优惠 · 易捷」：显示摘要；大号的「最近加油」换成它：显示前 3 条。
4. 当天再打开油记不重查；点开的一页里「重新查」会重查。
5. 记加油时从易捷选交易：最多等一批，不会卡住十几秒。
