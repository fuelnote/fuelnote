# FuelNote Check：手机上的自动检查

开发用，不随油记发布。电脑通过手机上开的端口触发检查，结果和截图传回电脑，代替一部分手机验收。

## 它做什么

- **识别**（`recognize`）：从电脑上的采样服务取保单文件（`XXYH_ROOT/materials/insurance/`），在手机上用油记的 `readPolicyFiles`、`scanPolicyFile` 读出保单和交强险标志，电脑和 `XXYH_ROOT/out/insurance/expected.json` 逐项比较。读不出文字的 PDF 用这一页上的 WebView 截图识别。PDFKit 取出的原文一起传回，`out/insurance/pdfkit.jsonl` 里还没有的由电脑补上，所以新加的保单不用再跑 Probe。
- **记账**（`ledger`）：电脑按本机数据（`expected.json`、最新的小熊云备份）生成计划，手机在检查用的账本上用本机测试车做一遍并逐步核对：导入各年保险、补到小熊里已有的费用（保留原金额或改成合计）、改优惠、改付款日期、续保提醒、删除；最后备份成 zip，删掉本机的原件再恢复，核对原件都回来、恢复前的副本写在 Check 自己的文件夹、Check 里不运行自动备份；再写一份立即备份，核对恢复列表的分组、打开一份能读出记录、能删掉，Check 里的备份不带凭据（不读钥匙串）；最后用编造的凭据和内存里的密钥核对：原生 HMAC 派生和标准 PBKDF2 一致、派生约 1 秒且界面照常响应、带凭据的 zip 写入不再派生、用密码解开拿回同一个密钥、密码不对时报错。
- **截图**（`shots`）：用记账之后的账本渲染真实页面（保单详情、编辑表单、保险页的续保提醒），浅色、深色各一张，页面撑高后一张图看到整页。
- **油耗与费用**（`split`，1.6）：电脑把最新的小熊云备份发给手机，手机在检查用的文件夹里导入选中的那辆车（和「设置 › 小熊油耗」的导入相同，`importCars`，不连小熊），照记账的做法导入各年保单；再核对油耗的统计只算加油、费用和保养合成一行只算一次、费用页和费用统计不含车险（合计、笔数、各类别、每年）、保险页的年数和只有金额的笔数、`widget.json` 只算加油，期望值由电脑用同一套纯函数从同一份备份算出。2.1 起再记一条保养（填了项目另存保养记录、费用页合成一行），改里程和项目、看导出的格式、删掉，数据回到原样。最后截图：油耗的记录和统计、费用的记录和统计、记费用、保险页、2021 年的保单详情（1.6.0-beta.4），记保养（新记、编辑第五次保养、保养项目页）。

- **导出**（`export`，2.0.0-beta.6）：电脑把最新的小熊云备份发给手机，手机在检查用的文件夹里导入那辆车，直接导出应和云端逐字段相同；再改一条加油、删最早的一笔费用、记一笔带门店的费用和一条用新油站的加油，只有这几条变化、门店写在备注末尾、新油站补上、离线算的条数对。账本和生成的备份交回电脑，电脑用同一套纯函数再算一遍逐字段比较。只生成，不上传。截图：导出预览、小熊里有改动（只在截图里假设小熊改了一笔金额、新记了一笔）。
- **权益**（`benefits`，1.7，要在 `split` 之后）：电脑把 `XXYH_ROOT/out/benefits/benefits.json`（用户的车险赠送原文和条目、套餐、门店）发给手机，在 `split` 导入的那辆车上加门店；用 Scripting 助手识别车险赠送的原文（发送前去掉个人信息）和套餐截图，和手动整理的条目数比（套餐的每一项都应是次数，名称、售价、有效期都要认出）；添加车险赠送、套餐（同时记一笔维修保养费用），记一笔用了权益的维修保养费用、记一次使用，改一批的有效期，删除用过的卡（费用不动）；核对剩余、分组和顺序、续保提醒的赠送、保单详情的「赠送」一行、费用的金额、备注和门店（2.0 起门店存在费用上，备注只留用户写的）、权益抵扣、账本里的引用都找得到。截图：权益页、一批、权益详情、已用完和已过期、添加权益（识别后）、编辑权益、编辑一批、记一次使用、使用权益、用了权益的费用、选择门店、门店详情、2026 年的保单详情。门店用全称，没有位置。
- **养修**（`service`，2.3.0-beta.2 起，要在 `benefits` 之后）：电脑把沃尔沃插件导出的进店（`XXYH_ROOT/out/plugin_data/service.json`，契约的格式，结算备注里的电话已去掉；2.3.0-beta.3 起，插件的 `tools/export.ts` 生成）发给手机，手机在检查用的文件夹里把它当作沃尔沃这个数据源核对：从沃尔沃选列出 10 次、新的在前；2026/4/3 填好的项目、说明、实付、里程，换了机油标题空着、灰字写第几次保养，这里的维修保养券和基础保养已被 `benefits` 用掉所以不先勾，门店按经销商名称找到，结算明细加起来是自付；保存后一笔费用和保养记录，存下结算明细和来源「沃尔沃」，门店不写经销商代码；编辑标题、清空后回到第几次保养；再选一次报「可能重复」；删掉；2024/10/11 另记两笔补漆（标题是沃尔沃给的）；最后记下 2024/10/11 的三笔。截图：选进店页、填好的记费用（2024/10/11）、编辑补漆（标题、来源、结算明细）、使用权益（新旧工单的对照）、保养项目、门店详情。不联网、不读钥匙串。「可能重复」是系统的操作表，截不到，要在手机上看。
- **数据源插件**（`plugin`，2.2.0-beta.1）：在检查用的文件夹里核对脚本目录列得出已装的脚本、读得到示例插件的 `fuelnote.json` 和 `script.json`；添加示例插件（调一次 `describe`）、同一个再加被拦下、读状态（打码的账号、记下上次的结果）、读最近 30 天的加油交易（8 笔，再读用缓存）、按数据源读示例车、最近 7 天的停车和车况（2.3.0-beta.1）、示例插件的两次进店（2.3.0-beta.2）、调别的脚本被拦下、移除；最后把示例插件加回来给截图。接着（2.2.0-beta.3，要在 `split` 之后）：单价不同、站码不同的两笔不能合成；分两笔付的合成一条并保存（里程接在最近一次加油后面，油站按交易定）；再选其中一笔，里程冲突时报「可能重复」、不冲突时不是错误，最后删掉保存的那一条；编一次停在我的油站的到站停车，看按停车认出油站、提醒核对里程；没有停车时按交易坐标新建。截图：设置页（数据源一组）、添加插件、插件详情、选交易（单选、合成、不能合成）、填好的记加油、编辑从示例插件记的加油（最上面一行「来源」，2.3.0-beta.2）。要先装好示例插件（`npm run check:install` 会一起装），第一次在手机上新建空脚本「FuelNote 示例插件」并在开发服务器页面里选它同步一次。
- **什么都不接**（`bare`，2.3.0-beta.3，插件化设计第 8 节）：清空检查用的文件夹（新装），不添加插件、不填凭据：加一辆不选车型的车，手填两次加油（算出油耗）、一笔停车费、一笔填了项目的保养（另存保养记录）、一份手动填的交强险（同时记保险费用）、一张洗车次数卡和一笔用了它的洗车；核对数据源一处都没调：没有插件、没有「关联的数据源还没添加」，读停车、车况直接是空的，记费用没有「从<名称>选」，小组件没有车况。截图：记录页、设置页（数据源只有「添加插件」）、记费用。跑完要重新跑 `split`。
- **地图搜索**（`map`，2.2.0-beta.2，要在 `split` 之后）：用 `split` 导入的油站（最近用过的 10 个）在附近 200 m 搜加油站，最近的一个和账本的位置中位差不到 30 m（坐标换算对；不换算差约 480 m）；以最近用过的油站为中心搜附近的汽车服务（4 个关键字合起来，1500 m 内、按距离排、没有重复）；选第一家存进我的门店，再搜一次认得出、再选不新加；取得到手机现在的位置（第一次会弹定位权限）；搜索框按名称搜（以手机的位置为区域）搜得到它；搜不到时返回空列表而不是报错。最后加一家像 2.1 那样存着营业时间的门店给截图。截图：设置页（没有「油站搜索」）、选择门店的附近和搜索结果、门店详情（地图上选的、存着营业时间的）。只报个数、距离和耗时。
- **加满金额**（`fill`，2.4）：像 2.3 添加的示例插件那样去掉油价，打开时按版本重读 `describe`，多了油价；建一辆关联示例车的车（车型参数里油箱 55 L），读示例车况（剩余 32.5 L）；读油价（按手机的位置，取不到时按最近用过的油站），再读一次不调插件；「加满」一组是 ¥180 · 22 L、95# 挂牌价 8.00；小组件的摘要有价格；移除插件后只写升数，最后加回来。截图：记录页「当前」、车况详情。

## 不碰真实数据

- 启动时 `setDataRoot("FuelNoteCheck")`：账本、保单原件、小组件文件都在 App Group 的 `FuelNoteCheck/` 下；清空前会核对文件夹名。
- 不读写钥匙串、不连小熊、不读车况；只向电脑上的采样服务取保单文件。
- 例外：`benefits` 把车险赠送的原文（去掉手机号、证件号、车牌、车架号后）和套餐截图（`XXYH_ROOT/out/benefits/package.png`，有时才发）发给 Scripting 助手识别，和油记里添加权益时一样。
- 真实数据只在电脑的 `XXYH_ROOT` 里：计划由电脑生成后发给手机，结果和截图存到 `XXYH_ROOT/out/check/`，不进仓库。

## 用法

1. 电脑上开着开发服务器（`E:\scripting` 里 `npx scripting-cli start`）和采样服务（`npm run ocr-bridge`）。
2. `npm run check:install`：把这里的检查程序连同油记的代码复制到 `../FuelNote Check`。只写有变化的文件，先写临时文件再改名（直接覆盖时手机可能按旧内容重新运行）。
3. 第一次：手机上新建一个空脚本「FuelNote Check」，在开发服务器页面里选它，运行。之后改了代码再装一次，手机会自己用新代码重新运行（约 2 秒）。
4. 手机上这一页留在屏幕上、屏幕不锁。它向采样服务报到，地址写到 `XXYH_ROOT/out/check/phone.json`。
5. 电脑上：`XXYH_ROOT=E:/GitHub/xxyh npm run device-check`（加 `--wait` 时先等手机上打开新版的 Check：STAMP 和示例插件的版本都和电脑上的一样，最多 30 分钟。可以先在后台跑着，手机上一打开就检查）（或只跑一部分：`… device-check -- recognize ledger shots split benefits export service plugin map` 里选，另有 `bare`、`fill`、`presets`、`info`；`shots` 要在 `ledger` 之后，`split`、`bare` 会清空检查用的账本，`benefits` 要在 `split` 之后）。

改了 `runner.tsx` 后把 `STAMP` 加一，`/ping` 返回的 STAMP 就能确认手机跑的是新代码。

## 不能自动检查的

真的点按和手势（左滑删除、轻点徽章全屏显示、拨号、选文件、「识别扫描件」里的取消、推入和返回、记费用分段的切换、「+」的轻点）、真实的小熊导入和导出、标签栏、桌面上的小组件，仍要在手机上看。
